# Starship Theme Switching

This directory stores the selectable Starship configurations used by `stheme`.
The setup is intentionally local and simple so humans and coding agents can
understand it without relying on a separate theme manager.

## Layout

```text
~/.config/starship/
├── current.toml -> themes/<active-theme>.toml
└── themes/
    ├── herdr-dracula.toml
    └── tokyo-night.toml
```

`~/.zshrc` sets `STARSHIP_CONFIG` to `current.toml`. Do not point it directly at
an individual theme. `stheme` changes the symlink, so the selection persists in
new terminals and is normally visible at the next prompt in existing shells.

## Commands

```sh
stheme --list                 # Show installed themes and bundled presets
stheme herdr-dracula          # Select a custom/local theme
stheme tokyo-night            # Select an installed bundled preset
stheme catppuccin-powerline   # Generate and select a bundled preset
stheme --refresh tokyo-night  # Regenerate a bundled preset from Starship
```

Running `stheme` without arguments is equivalent to `stheme --list`. The active
installed theme is marked with `*`.

## Adding Custom Themes

Add `<name>.toml` under `~/.config/starship/themes/`, then run:

```sh
stheme <name>
```

Custom themes automatically appear in `stheme --list`. Do not use `--refresh`
with a custom theme: that option asks Starship to replace the file from one of
its compiled-in presets.

## Maintenance Notes

- Edit theme files under `themes/`, never `current.toml`.
- Do not replace `current.toml` with a regular file; it is the active selector.
- Bundled presets are snapshots generated by `starship preset` and can be
  refreshed explicitly after upgrading Starship.
- Starship's native `preset --list` cannot include custom themes, which is why
  the `stheme` wrapper owns local discovery and selection.

## Transient Prompts

Starship does not provide transient prompt support for Zsh. The shell loads
`olets/zsh-transient-prompt` from:

```text
~/.oh-my-zsh/custom/plugins/zsh-transient-prompt/
```

It is sourced after Starship initialization in `~/.zshrc`. Completed prompts
collapse to a lilac `❯`, while the current prompt keeps the full active theme.
To disable transience, remove its setup from the chezmoi source file
`dot_config/zsh/starship.zsh`, apply it, then start a new shell.

## Warp Prompt Behavior

The intended Warp experience differs from Ghostty and ordinary terminals:

| Terminal | Active input prompt | Completed command prompt |
| --- | --- | --- |
| Warp | Warp's native folder-style prompt | Compact lilac `❯` |
| Herdr panes, including Herdr launched from Warp | Full active Starship theme | Compact lilac `❯` |
| Ghostty and other terminals | Full active Starship theme | Compact lilac `❯` |

Native Warp shells are detected through `TERM_PROGRAM=WarpTerminal` without
`HERDR_ENV=1`. In that environment, `~/.config/zsh/starship.zsh` does not
initialize Starship and gives the transient-prompt plugin an empty full shell
prompt. This prevents the large Starship powerline region from appearing above
Warp's native input area while retaining the colored marker on completed
command blocks.

Herdr-managed shells always initialize Starship. Herdr's long-lived process can
inherit `TERM_PROGRAM=WarpTerminal` when launched from Warp, so `HERDR_ENV=1`
takes precedence over the Warp detection.

If Warp shows a large Starship region above its native folder prompt, the Warp
special case is missing or the shell predates the latest configuration. Open a
new Warp tab after applying changes because prompt hooks remain registered in
already-running shells.

To intentionally use Starship as Warp's active prompt instead:

1. Set Warp's **Settings > Appearance > Input > Input type** to
   **Shell (PS1)**.
2. Remove the `WarpTerminal` branch in `~/.config/zsh/starship.zsh` so Warp
   follows the normal `starship init zsh` path.
3. Start a new Warp session.

Make that policy change in the chezmoi source file
`dot_config/zsh/starship.zsh`, not only in the rendered home-directory file.
